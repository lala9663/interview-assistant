# 질문 은행과 평점 기준 예시

> 다루는 것: 직군·역량별로 채용 담당자가 검수한 질문(질문 은행)과, 역량의 점수마다 수준을 보여 주는 가상 답변(평점 기준 예시). 어디에 쓰고 쓰지 않는지, 금지 질문 규칙, CSV 형식.
>
> 상태: 구현됨 · 확인: 2026-10-30

둘 다 BGE-M3로 임베딩해 꼬리질문·채점·역량 사전 초안에 쓴다. API는 [api-contract.md](api-contract.md) "질문 은행·평점 기준 예시", 모델 선택 근거는 [model-selection.md](model-selection.md) 6장, 측정은 [embedding-benchmark.md](embedding-benchmark.md).

## 1. 어디에 쓰고, 어디에 쓰지 않나

| 쓰는 곳 | 어떻게 |
| --- | --- |
| 꼬리질문 즉시 후보 | 답변이 끝나면 비식별 답변을 임베딩해, 그 공고 직군·세션 역량 사전의 역량·그 차수(또는 모든 차수)의 **승인된** 질문과 꼬리질문 예시에서 가까운 것 1~2개를 바로 보여 준다(출처 "질문 은행"). 이어서 AI 후보가 스트리밍된다 |
| AI 꼬리질문의 예시 | 가까운 질문 4개(꼬리질문 예시 포함)를 프롬프트 `<example_questions>`에 넣는다. 먼저 보여 준 질문 은행 후보는 `<already_suggested>`로 넘겨 같은 뜻을 쓰지 않게 한다 |
| 같은 질문 거르기 | 이 면접과 이전 차수에서 이미 한 질문, 앞서 보여 준 후보와 의미 유사도가 `duplicate_threshold`(BGE-M3 0.85) 이상인 후보는 뺀다. 질문 은행 후보는 보이기 전에, AI 후보는 화면에 뜬 뒤 확인한다(임베딩이 카드를 늦추지 않게). 확인이 끝날 때까지 AI 후보는 쓸 수 없고, 같다고 나오면 카드가 흐려졌다가 "이미 한 질문과 비슷함" 한 줄로 접힌다. 빠진 후보도 남아 지표에 잡히고, 질문으로 기록할 수 없다(API 409) |
| 역량 사전 AI 초안 | 새 차수의 공고·JD와 가까운 다른 공고의 확정 역량 사전 2개까지를 예시로 준다 |
| 채점 기준점 | 세션 역량마다 그 직군의 승인된 평점 기준 예시(점수별 최신 하나, 그 직군에 없으면 다른 직군의 같은 역량 이름)를 채점 프롬프트 `<anchors>`에 행동 기준과 함께 넣는다 |

하지 않는 것 (테스트로 고정, `tests/test_retrieval.py`):

- **기준 예시와의 유사도로 점수를 매기지 않는다.** 외운 답변이나 예시와 소재가 같은 답변이 유리해져 공정성을 해친다. 기준점은 직군·역량으로만 고르고 지원자 답변과의 유사도는 계산하지 않는다. 점수는 모델이 답변을 행동 기준(BARS)에 비추어 읽은 값이다. 테스트: 지원자 답변과 글자까지 같은 5점 예시를 넣어도 모델이 2점이라 하면 2점, 채점 중 임베딩을 부르면 실패, 채점 모듈에 검색·유사도 코드가 없음.
- **지난 지원자의 실제 답변을 예시나 검색 대상으로 쓰지 않는다.** 수집 목적 밖의 이용이고, 지난 면접의 편향이 그대로 옮는다. 벡터 저장소는 회사가 쓴 텍스트(질문 은행, 평점 기준 예시, 확정 역량 사전)만 받는다(DB CHECK `owner_type IN ('question', 'rubric', 'competency_set')`). 평점 기준 예시는 저장된 지원자 답변과 거의 같으면(5글자 조각 60% 이상 겹침) 거절하고, 연락처·주민번호 모양도 거절한다. 테스트: 채점 프롬프트에 다른 지원자의 답변이 없음, 답변을 복사한 예시 409, 다른 owner_type 벡터는 DB가 거부.

## 2. 질문 은행

| 칸 | 내용 |
| --- | --- |
| 직군·역량 | 공고가 아니라 직군(공정개발, SW개발 …)과 역량에 묶어 여러 공고가 같이 쓴다. 고를 수 있는 역량은 그 직군의 질문 은행·평점 기준과 공고들의 확정 역량 사전에 있는 것 |
| 차수 | 1차, 2차 …(공고마다 이름이 달라 위치로만). 비우면 모든 차수 |
| 질문, 의도 | 행동 사례를 묻는 질문 하나, 확인하려는 것 |
| 좋은 꼬리질문 예시 | 그 질문 뒤에 이어 물을 만한 질문(10개까지). 답변이 예시와 가까우면 예시가 그대로 후보로 나온다 |
| 상태 | 초안 → 승인 → 폐기(되살리면 초안). **승인된 것만** 검색되고 AI에 보인다. 승인된 질문을 고치면 초안으로 돌아간다 |
| 작성·승인자 | 초안은 누구나 쓰고, 승인·폐기·되살리기·CSV 가져오기·AI 확인은 관리자(채용 담당자 역할 대신, SSO 그룹이 생기면 바꾼다). 모두 감사 로그 |

화면: 사이드바 "질문 은행"(`/question-bank`). 직군·역량·차수·상태 필터와 검색, 질문 추가(쓰는 동안 금지 질문 경고), 승인(경고가 있으면 확인 단계), AI 확인, 폐기·되살리기, CSV 가져오기(미리 보기 → 가져오기), 같은 화면의 "평점 기준 예시" 탭.

### CSV 형식

```
직군,역량,차수,질문,의도,꼬리질문 예시
공정개발,데이터 기반 분석,1차,FDC 알람이 잦을 때 실제 이상과 오탐을 어떻게 가렸나요?,알람 품질,알람 기준은 누가 정했나요? | 오탐을 줄인 뒤 결과는?
```

- 첫 줄은 열 이름(한국어 또는 `job_family, competency, round, question, intent, follow_ups`). 직군·역량·질문 열은 필수.
- 차수는 `1`, `1차` 또는 비움(모든 차수). 꼬리질문 예시는 `|`로 나눈다.
- UTF-8(BOM 포함)과 엑셀 한글 기본 저장 형식(CP949) 모두 읽는다. 2MB, 5,000행까지.
- 같은 직군·역량에 같은 질문(공백 무시)이 이미 있으면 건너뛴다. **모두 초안으로** 들어오고 승인은 하나씩 한다.
- 미리 보기는 추가·건너뜀·오류(행 번호와 이유)·금지 질문 경고를 보여 주고 아무것도 저장하지 않는다.

## 3. 금지 질문 검사

채용 면접에서 직무와 무관하게 물으면 안 되는 질문을 규칙으로 찾아 **경고**한다(`ai/question_rules.py`, 프론트 모의 API에 같은 규칙). 경고가 있어도 저장은 되고, 승인하려면 "경고를 확인하고 승인"을 눌러야 한다(API `confirm_warnings`). 승인 기록에 확인한 경고의 범주가 남는다. 직무와 관련 있으면 예외일 수 있어(예: 교대 근무가 직무 조건인 경우의 근무 가능 시간은 묻되 혼인 여부는 묻지 않는다) 판정이 아니라 사람이 읽을 경고로 둔다.

근거: 채용절차의 공정화에 관한 법률 제4조의3(직무 수행에 필요하지 않은 신체적 조건, 출신 지역·혼인 여부·재산, 직계 존비속·형제자매의 학력·직업·재산 정보를 요구하거나 수집하지 않는다), 남녀고용평등법 제7조(모집·채용에서 혼인·임신·출산 등을 이유로 한 차별, 직무와 무관한 신체 조건·미혼 조건), 국가인권위원회법 제2조 제3호(종교, 나이, 출신 지역·국가·민족, 용모 등 신체 조건, 혼인 여부·임신·출산·가족 형태, 정치적 의견, 병력, 성적 지향, 학력 등을 이유로 한 차별), 블라인드 채용 지침(출신 학교).

| 범주 | 화면 이름 | 이런 질문 | 예외로 지우는 표현 |
| --- | --- | --- | --- |
| family | 가족 사항 | 부모님 직업·직장·학력·재산, 가족 관계·구성, 형제 관계, 외동·장남·막내, 한부모 가정 | "가족 같은 팀 분위기" |
| origin | 출신 지역·국가·민족 | 고향, 본적, 어디 출신, 사투리, 국적·민족·인종 | |
| marriage | 혼인·연애 | 결혼, 기혼·미혼·이혼·재혼, 배우자, 애인·연애 | "장애인"의 "애인" |
| pregnancy | 임신·출산·육아 계획 | 임신, 출산, 자녀 계획, 아이가 있는지, 육아휴직 계획 | |
| religion | 종교 | 종교, 신앙, 교회·성당·절 | |
| appearance | 외모·신체 조건 | 외모·용모, 키·몸무게·체격, 문신 | "장비 키 값", "API 키", "얼굴 인식" |
| age | 나이 | 나이, 몇 살, 몇 년생, 띠 | |
| wealth | 재산·경제 사정 | 재산, 자가·전세·월세, 부채, 경제 사정 | "경제성", "경제적 효과" |
| politics | 정치 성향·사상 | 정치 성향, 지지 정당, 투표, 노조 가입 | "투표로 정했다", "보수적으로" |
| health | 건강·병력·장애 | 병력, 지병, 건강 상태, 정신과, 복용 약, 장애 여부·등급 | "서비스 장애 대응"(장애는 "장애가 있으신가요"처럼 사람을 물을 때만) |
| orientation | 성별 고정관념·성적 지향 | 성적 지향, "여자라서/남자라서", 여성이라 야근·출장·체력 | |
| school | 출신 학교 (블라인드) | 출신 학교·대학, 어느 대학 나왔는지, 학벌·명문대 | |

- 규칙은 단어만이 아니라 앞뒤 문맥을 본다(예: "부모님" + "직업·학력·무슨 일"). 업무에서 흔한 표현은 먼저 지운다(위 표 오른쪽 열).
- **AI 확인**(question-check-v0.1, 관리자): 규칙이 놓친 것을 LLM이 한 번 더 본다. 질문과 꼬리질문 예시만 보내고 지원자 데이터는 없다. AI 경고는 `source: ai`로 붙고, 질문을 고치면 지워진다. fake LLM은 규칙과 같은 답을 하므로 실제 모델을 붙여야 의미가 있다.
- 규칙 시험(`tests/test_retrieval.py::test_prohibited_question_rules`): 범주마다 예시 질문이 정확히 그 범주로 잡히고, 업무 질문("기억에 남는 장애 하나를 탐지부터 회고까지", "CVD 증착 균일도", "보수적으로 일정을") 6개는 경고가 없다. 시드의 승인된 질문 37개는 경고가 없고, 일부러 넣은 초안("결혼 계획이 있다면 교대 근무나 해외 출장에 지장은 없을까요?") 하나만 걸린다.
- 같은 범주 목록을 채용 사이트 연동이 받지 않는 항목(가족·신체·출신지·혼인·재산·종교·정치·건강·성별)에도 쓴다([site-intake-spec.md](site-intake-spec.md)).

## 4. 평점 기준 예시

| 칸 | 내용 |
| --- | --- |
| 직군·역량·점수 | 1~5점 중 하나. 역량마다 점수별로 하나씩이 기본이고, 여러 개면 가장 최근에 승인한 것을 쓴다 |
| 질문, 예시 답변, 이 점수인 이유 | 사람이 새로 쓴 가상 답변. 이유는 행동 기준의 어느 수준과 맞는지 |
| 상태 | 초안 → 승인 → 폐기. 승인된 것만 채점 프롬프트에 들어간다 |

- **겹침 경고**: 같은 직군·역량의 다른 점수 승인 예시와 의미 유사도가 `duplicate_threshold` 이상이면 "3점 예시와 거의 같습니다"로 보여 준다. 기준점끼리 겹치면 점수 사이가 흐려져 채점이 흔들린다. 경고만 하고 막지 않는다. 임베딩을 여기에 쓰는 이유는 기준점의 일관성이지 채점이 아니다.
- 채점 프롬프트(score-v0.4)는 기준점을 "점수 수준을 보여 주는 가상 답변이며, 표현·소재가 비슷한지로 점수를 정하지 말라"는 지시와 함께 준다.

## 5. 데모 시드

프론트 `frontend/src/mocks/data/question-bank.ts`가 원본이고 `node scripts/export_mock_data.mjs`로 `demo/mock_data.json`에 들어간다. 시드 공고의 직군·역량에 맞춘 가상 질문 40개(공정개발 24: 1차 4개 역량 16·2차 3개 역량 6·초안 1·폐기 1, SW개발 11: 4개 역량 10·초안 1, 디자인 5: 3개 역량), 평점 기준 예시 16개(공정개발 "공정 문제 해결"·"데이터 기반 분석", SW개발 "시스템 설계" 각 1~5점, 초안 1). 데모 대본 답변(식각 CD·FDC·RF, 장애 대응 …)과 맞물리게 썼다. 벡터는 시드하지 않고 서버가 기동할 때 활성 임베딩 모델로 만든다.
