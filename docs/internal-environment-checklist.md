# 사내 환경 확인 체크리스트

2026-10-28 · 원본: [Claude Doc](https://claude.ai/artifact/6Q9Kf1kRcjAUgCa7phVCso) (답은 원본이나 인쇄본에 채우고, 바뀌면 이 사본도 고친다)

## 쓰는 법

이 표의 답으로 외부 개발 환경(Python 버전, DB, LLM 모델, Docker 이미지)을 사내와 같게 맞춘다. 맞춰 두면 사내에서 생긴 문제를 밖에서 재현할 수 있어서, 반출 노트가 짧아지고 왕복 횟수가 준다.

- **우선순위:** 1순위는 다르면 결과가 바뀌는 항목이고, 첫 방문에 꼭 받아 온다. 2순위는 첫 본 반입 전까지, 3순위는 파일럿 전까지 확인하면 된다.
- **확인하는 곳:** 대부분 반입 없이 인프라·보안 담당에게 묻거나 사내 PC에서 직접 보면 된다. 물어서 알 수 없는 것(예: 이 패키지가 실제로 설치되는가)만 "환경 조사 키트"를 반입해서 확인한다.
- **답 칸:** 숫자와 이름을 그대로 적는다(예: Ubuntu 22.04, Python 3.11.9). 모르면 "모름"과 함께 누구에게 물어야 하는지 적는다.
- **적으면 안 되는 것:** 서버 주소·IP·호스트명, 계정과 비밀번호, API 키, 지원자 정보, 사내 시스템 화면 내용. 이 양식 자체를 들고 나와도 되는지는 8장에서 먼저 확인한다.

## 1. 사내 LLM

가장 먼저 확인할 항목이다. 모델이 다르면 같은 프롬프트로도 꼬리질문·채점·서류 선별 결과가 달라진다. 외부에 같은 모델을 띄워야 품질 문제를 밖에서 고칠 수 있다.

**예상 모델: Gemma 4** (추정, 확인 필요). Google이 만들었고 Apache 2.0이라 라이선스·출처 문제는 없다. 크기가 E2B·E4B·12B·26B-A4B(MoE)·31B 중 무엇인지, 양자화, 서빙 도구, 추론 모드(think) 설정을 함께 확인한다. 크기가 두 개 이상 제공되면 모두 적는다.

| 순위 | 항목 | 왜 필요한가 | 답 |
| --- | --- | --- | --- |
| 1 | 우리 시스템이 쓸 수 있는 LLM이 있는가 (플랫폼 제공 / 직접 설치 / 없음) | 없으면 GPU 서버에 직접 설치해야 한다 | |
| 1 | 모델 이름과 버전 (예: Qwen3-32B, EXAONE 4.0 32B) | 외부에 같은 모델을 띄운다 | |
| 1 | 양자화 여부 (fp16 / int8 / int4) | 같은 모델도 양자화에 따라 답이 달라진다 | |
| 1 | API 형식 (OpenAI 형식 `/v1/chat/completions` / 자체 형식) | OpenAI 형식이면 지금 provider가 그대로 붙는다 | |
| 1 | 서빙 도구 (vLLM / Ollama / SGLang / 플랫폼 게이트웨이 / 모름) | 외부에 같은 도구로 띄운다 | |
| 2 | 컨텍스트 길이 (토큰) | 서류 전체나 이전 차수 요약을 한 번에 넣을 수 있는가 | |
| 2 | 스트리밍 지원 | 꼬리질문 카드를 글자가 나오는 대로 보여 준다 | |
| 2 | JSON 응답 강제(structured output) 지원 | 채점·프로필 구조화가 JSON에 기대고 있다 | |
| 2 | 도구 호출(tool calling) 지원 | 나중에 챗봇·에이전트를 직접 만들 때 필요 | |
| 2 | 동시 요청·분당 토큰 한도 | 면접 여러 개가 동시에 돌 때 버티는가 | |
| 2 | 대략적인 응답 속도 (첫 글자까지 몇 초) | 꼬리질문 목표(답변 끝 후 3초) 안에 들어오는가 | |
| 2 | 요청·응답을 어디에 얼마나 기록하는가 | 비식별 지원자 텍스트가 로그에 남는다 | |
| 3 | 중국 모델(Qwen, DeepSeek) 사용 허용 여부, 사내에서 쓸 수 있는 모델 목록 | 후보 모델을 정할 때 | |
| 3 | 임베딩 모델도 제공하는가 | 지금은 BGE-M3를 직접 돌린다. 제공되면 비교한다 | |

## 2. 서버 OS·CPU·Python

여기가 다르면 반입한 패키지가 설치되지 않는다. onnxruntime(BGE-M3), CTranslate2(Whisper), PaddleOCR처럼 OS·CPU별로 따로 빌드된 라이브러리가 많기 때문이다.

| 순위 | 항목 | 왜 필요한가 | 답 |
| --- | --- | --- | --- |
| 1 | 서버 OS와 버전 (예: Ubuntu 22.04, RHEL 8.9, Windows Server 2022) | 대상 OS용 패키지를 묶어 반입한다 | |
| 1 | CPU 종류 (x86_64 / ARM) | 패키지 빌드가 다르다 | |
| 1 | Python을 설치할 수 있는가, 버전은 (지금 3.12 기준) | 3.12가 안 되면 외부도 그 버전으로 내린다 | |
| 1 | 개발자가 패키지를 직접 설치할 권한이 있는가 (관리자 권한, 신청 절차) | 설치 방식을 정한다 | |
| 2 | uv를 쓸 수 있는가 (안 되면 pip) | 설치 안내서를 그에 맞춘다 | |
| 2 | 서버 메모리와 CPU 코어 수 | Whisper·BGE-M3·OCR을 한 서버에서 돌릴 수 있는가 (이 노트북 16GB에서는 돌아감) | |
| 2 | 디스크 여유 공간 | 모델 파일만 수십 GB(Whisper large-v3 약 3GB, BGE-M3 약 2GB, LLM은 그 이상) | |
| 3 | 서버 시간대·로케일 (한글 Windows면 CP949) | 파일명·로그의 한글 깨짐 | |
| 3 | LibreOffice·Tesseract 같은 프로그램을 설치할 수 있는가 | 구형 .doc/.ppt 변환에 LibreOffice가 필요 | |

## 3. 컨테이너·GPU

Docker를 쓸 수 있으면 환경 맞추기가 가장 쉽다. 외부에서 만든 이미지를 그대로 반입하면 OS·Python·패키지가 한꺼번에 같아진다. GPU는 실시간 전사가 가능한지와 쓸 수 있는 LLM 크기를 정한다.

| 순위 | 항목 | 왜 필요한가 | 답 |
| --- | --- | --- | --- |
| 1 | Docker(또는 Podman) 사용 가능 여부 | 가능하면 이미지로 반입한다 | |
| 1 | 우리 시스템이 쓸 수 있는 GPU가 있는가 | 없으면 면접 후 전사가 기본이 된다 | |
| 1 | GPU 종류·개수·메모리 (예: A100 80GB × 2) | 올릴 수 있는 LLM 크기와 Whisper 실시간 여부 | |
| 2 | 컨테이너 이미지 반입 허용 여부와 사내 이미지 저장소(registry) | 이미지 파일(tar)을 반입할지 사내 저장소에 올릴지 | |
| 2 | 허용된 기본 이미지 (예: 사내 승인 베이스 이미지만) | 외부 이미지를 그 위에서 만든다 | |
| 2 | NVIDIA 드라이버·CUDA 버전 | GPU용 패키지 버전을 맞춘다 | |
| 2 | GPU를 다른 팀과 나눠 쓰는가 (예약·할당 방식) | 면접 시간에 GPU를 확보할 수 있는가 | |
| 3 | Kubernetes 같은 운영 플랫폼을 써야 하는가 | 배포 방식과 문서 | |

## 4. DB·파일 저장소

코드는 SQLite·PostgreSQL·MySQL 어느 것이든 돌지만, 테스트는 실제로 쓸 엔진과 버전으로 해야 한다. PostgreSQL이면 벡터 검색(pgvector)까지 DB 안에서 할 수 있다.

| 순위 | 항목 | 왜 필요한가 | 답 |
| --- | --- | --- | --- |
| 1 | 쓸 수 있는 DB 엔진과 버전 (PostgreSQL / MySQL / 기타) | 외부 개발 DB를 같은 엔진·버전으로 맞춘다 | |
| 2 | DB를 직접 설치하나, DBA가 내주는 사내 DB를 쓰나 | 마이그레이션(테이블 생성) 권한이 있는가 | |
| 2 | PostgreSQL이면 pgvector 확장 설치 가능 여부 | 질문 은행 검색을 DB 안으로 옮길 수 있는가 | |
| 2 | 서류 원본·녹음 파일 저장 위치 (서버 디스크 / 사내 객체 저장소 / NAS) | 원본 영역을 어디에 둘지 | |
| 2 | 원본 영역 암호화 요구사항과 키 관리 방식 (사내 KMS 등) | 지금은 환경변수 키(Fernet)를 쓴다 | |
| 3 | 백업·보관 기간 규정 (지원서·녹음 파기 시점) | 자동 삭제 기능 설계 | |

## 5. 네트워크·패키지 미러·모델 파일

사내 패키지 미러가 있으면 반입 꾸러미가 코드만으로 작아진다. 없으면 모든 패키지와 모델 파일을 함께 반입해야 한다. 관리자 화면의 "모델 다운로드"는 Hugging Face에서 받기 때문에 인터넷이 막히면 동작하지 않는다.

| 순위 | 항목 | 왜 필요한가 | 답 |
| --- | --- | --- | --- |
| 1 | 서버에서 인터넷 접속 가능 여부 (완전 차단 / 프록시 경유 / 일부 허용) | 모델·패키지를 반입해야 하는가 | |
| 1 | 사내 PyPI 미러 (Nexus, Artifactory 등) | 있으면 Python 패키지를 반입하지 않는다 | |
| 1 | 사내 npm 미러 | 없으면 프론트를 빌드한 결과물만 반입한다 | |
| 2 | 사내 Hugging Face 미러나 모델 저장소 | 없으면 모델 파일을 반입한다 | |
| 2 | 사내 Git 저장소 (GitLab, Bitbucket 등) | `upstream`·`internal` 브랜치를 운영할 곳 | |
| 2 | 사용자 PC에서 서버까지 열어야 하는 포트·방화벽 신청 절차 | 웹 화면(HTTPS)과 실시간 전사(SSE·WebSocket) | |
| 2 | 사내 TLS 인증서 발급 방식 | 브라우저 마이크는 HTTPS에서만 동작한다 | |
| 3 | 시간 동기화(NTP) | 서명 검증·감사 로그 시각 | |

## 6. 사용자 PC·브라우저·보안 프로그램

면접관이 실제로 쓰는 PC에서 화면과 마이크가 동작하는지 보는 항목이다. 보안 프로그램은 물어보는 것보다 환경 조사 키트로 직접 확인하는 게 확실하다.

| 순위 | 항목 | 왜 필요한가 | 답 |
| --- | --- | --- | --- |
| 1 | 면접관 PC의 브라우저와 버전 (Chrome / Edge / 기타) | 프론트 빌드 대상과 기능 지원 | |
| 2 | 면접실 PC에서 브라우저 마이크 사용이 허용되는가 | 실시간 전사의 전제 | |
| 2 | DLP·보안 프로그램이 막는 것 (로컬 포트, WebSocket, 파일 업로드, 녹음) | 업로드·실시간 화면이 막히지 않는가 | |
| 2 | 화면 해상도·모니터 수 (면접 중 전사와 질문 카드를 함께 볼 수 있는가) | 실시간 면접 화면 배치 | |
| 2 | 면접실 마이크 장비 (노트북 내장 / 회의용 마이크 / 개인 마이크) | 전사 품질과 화자 구분 방식 | |
| 3 | 비대면 면접에 쓰는 화상회의 도구 | 참가자별 오디오를 따로 받을 수 있는가 | |
| 3 | 보통 한 번에 면접이 몇 건 동시에 도는가 | 서버·GPU 용량 계산 | |

## 7. 인증·연동: SSO, 에이전트 플랫폼, 채용 사이트

이 항목들은 외부에서 따라 만들 수 없다. 그래서 "어떤 형식인가"만 알아 와서, 외부에서는 같은 형식의 가짜(fake)를 만든다. 내부에서는 설정만 바꾸면 되게 하는 것이 목표다.

| 순위 | 항목 | 왜 필요한가 | 답 |
| --- | --- | --- | --- |
| 1 | 연결할 에이전트 플랫폼 이름 (FabriX Agent Studio 등) | MCP 연결 방법이 플랫폼마다 다르다 | |
| 2 | 플랫폼의 MCP 지원 방식·버전 (streamable HTTP / SSE) | 지금 MCP 서버는 stdio와 streamable HTTP를 지원한다 | |
| 2 | 플랫폼이 "질문한 사용자" 신원을 도구에 넘기는 방법 (OAuth / SSO 토큰 전달 / 헤더 / 서비스 계정 하나) | 서비스 계정 하나면 면접관별 권한이 무력해진다 | |
| 2 | 플랫폼 도구 등록 절차·보안 심사·도구 수·응답 크기·시간 제한 | 도구 설계 조정 | |
| 2 | 플랫폼이 실행 전 사람 확인 화면을 주는가 | 지금은 "제안 → 웹에서 확인" 방식 | |
| 2 | SSO 방식 (SAML / OIDC / 사내 자체) 과 연동 신청 절차 | 로그인을 붙이는 방식 | |
| 2 | 면접관·관리자 권한을 나눌 수 있는 사내 조직·권한 정보 연동 (부서, 직급, 그룹) | 권한 모델 | |
| 3 | 면접관 일정을 가져올 사내 캘린더 (Outlook / 사내 그룹웨어) | 지금은 면접관이 가용 시간을 직접 입력한다 | |
| 3 | 채용 사이트 연동 담당 부서와 일정 | 수신 명세([site-intake-spec.md](site-intake-spec.md))를 넘길 곳 | |
| 3 | 최종 결과를 채용 사이트에 반영하는 방식 | 지금은 담당자가 직접 기록한다 | |

## 8. 반입·반출 규정

작업 주기를 정하는 항목이다. 반입 승인에 걸리는 시간이 곧 외부·내부 왕복 한 번의 길이다. 수기 반출 허용 범위는 이 양식을 들고 나오기 전에 먼저 확인한다.

| 순위 | 항목 | 왜 필요한가 | 답 |
| --- | --- | --- | --- |
| 1 | 반입 신청부터 사용까지 걸리는 기간과 가능한 주기 | 주 1회 반입이 가능한가 | |
| 1 | 반입 허용 파일 형식과 크기 제한 (zip, wheel, 컨테이너 이미지, 수 GB 모델 파일) | 반입 꾸러미 구성 | |
| 1 | 수기 반출 허용 범위 (코드 수정 설명, 오류 코드, 환경 버전 같은 것을 적어 나가도 되는가) | 반출 노트 양식을 규정에 맞춘다 | |
| 2 | 오픈소스 라이선스 검토 절차와 금지 라이선스 (GPL, AGPL 등) | 의존성 목록을 미리 맞춘다 (예: PyAV에 들어 있는 GPL 코덱) | |
| 2 | AI로 생성한 코드의 반입·사용 허용 여부와 조건 | 개발 방식 전체의 전제 | |
| 2 | 악성코드 검사에서 자주 걸리는 파일 (실행 파일, DLL, 압축 안 압축) | 꾸러미를 미리 풀어 둔다 | |
| 2 | 내부 OpenCode가 쓰는 모델과 저장소 접근 범위 | 반출 노트 요약을 맡길 수 있는가 | |
| 3 | 가상 지원서·면접 녹음(테스트 데이터)을 반입해도 되는가 | 내부 테스트용 | |
| 3 | 실제 지원자 데이터로 파일럿을 하려면 필요한 승인 (정보보호, 개인정보 영향평가, 지원자 동의) | 파일럿 일정 | |

## 다녀와서

답을 받으면 외부에서 아래를 맞춘 뒤 첫 본 반입 꾸러미를 만든다. "모름"으로 남은 1순위 항목은 환경 조사 키트로 먼저 확인한다.

| 답이 정하는 것 | 외부에서 하는 일 |
| --- | --- |
| 1장 사내 LLM | 같은 모델·양자화·서빙 도구로 개발용 서버를 띄우고, LLM provider 기본값과 프롬프트를 그 모델 기준으로 맞춘다 |
| 2·3장 OS·Python·Docker·GPU | 같은 OS·Python 버전의 개발 환경(가능하면 Docker 이미지)을 만들고, 대상 플랫폼용 패키지 묶음을 만든다. GPU가 없으면 면접 후 전사를 기본으로 둔다 |
| 4장 DB | 개발·테스트 DB를 같은 엔진·버전으로 바꾼다 |
| 5장 네트워크·미러 | 미러가 없으면 wheel·빌드된 프론트·모델 파일을 모두 꾸러미에 넣는다 |
| 6장 사용자 PC | 프론트 빌드 대상 브라우저를 맞추고, 마이크·실시간 전사 기능을 그에 맞게 켜거나 끈다 |
| 7장 인증·연동 | 같은 형식의 가짜 SSO·플랫폼을 만들고, 내부에서는 설정만 바꾸면 되게 한다 |
| 8장 반입·반출 규정 | 반입 주기와 꾸러미 형식을 정하고, 반출 노트 양식을 허용 범위에 맞춘다 |
