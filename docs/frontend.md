# 프론트엔드 (면접관 UI)

> 다루는 것: `frontend/`의 스택, 화면 목록, 모의 API 모드와 백엔드 연결 모드, 검사·빌드, 의존성 규칙.
>
> 상태: 구현됨 · 확인: 2026-10-30

`frontend/`. Vite + Vue 3 + TypeScript(strict, `vue-tsc`), Tailwind CSS v4 + shadcn-vue 방식 컴포넌트(Reka UI), TanStack Query(`@tanstack/vue-query`), Vue Router, MSW, Chart.js(`vue-chartjs`), vue-sonner, lucide 아이콘(`@lucide/vue`). 명령 팔레트는 Reka UI Listbox, 화면 전환 효과는 Vue `<Transition>`과 CSS만 쓴다. 테스트는 Vitest + Testing Library(Vue) + MSW(node), 린트는 eslint-plugin-vue + typescript-eslint. 폰트는 Pretendard(OFL)를 npm 패키지에서 자체 호스팅한다. Node 24 이상. 이전 React 버전은 git 이력(`93a1780`)에 있다.

## 화면

대시보드, 공고·역량 사전(FR-02, 채용 사이트 공고 번호 연결, "전형" 탭: 차수 추가·순서·이름·설정, 차수별 역량 사전과 사전 질문), 서류 선별(FR-01·03, 수신 경로·진행 표시·차수 필터, 다음 차수를 기다리는 지원자는 상세에서 바로 면접 잡기: 차수·지원자 고정, 면접관·길이·기간 → 함께 비는 시간; 아래 "서류 선별"), 면접 목록, 실시간 면접(FR-04~08, 이전 차수 요약·이어 질문), 평가 결과(FR-07·08, N차 결정·확인할 점, 내 점수를 내기 전에는 AI 점수를 가림; 아래 "평가"), 면접관 스케줄(FR-09, 차수부터 고르는 면접 잡기), 질문 은행(직군·역량별 검수 질문과 평점 기준 예시, [question-bank.md](question-bank.md)), 관리자 > 모델 설정(관리자만, [ai-models.md](ai-models.md)), 관리자 > 연동 현황(관리자만, 채용 사이트가 보낸 이벤트와 처리 결과), 관리자 > 꼬리질문 지표(관리자만, 출처별 채택률·첫 후보까지 시간·걸러낸 수). 실시간 면접의 마이크는 [audio-input.md](audio-input.md). 다크 모드 기본(시스템 설정 따름), Ctrl/⌘+K 명령 팔레트.

요구사항 번호(FR-01 …)는 화면에 보이지 않는다(사이드바·페이지 머리·명령 팔레트 표시에서 뺐다). 명령 팔레트 검색어로는 남아 있어 "FR-07"로 찾을 수 있다.

경로는 `frontend/src/router.ts`: `/`, `/postings`, `/postings/:postingId`, `/screening/:postingId?`, `/sessions`, `/sessions/:sessionId/live`, `/sessions/:sessionId/evaluation`, `/schedule`, `/question-bank`, `/admin/models`, `/admin/intake`, `/admin/follow-up-metrics`.

차수 표기 규칙: 차수는 어느 화면에서나 같은 회색 배지(`RoundBadge`, 짧게 "1차", 헤더는 굵게 "2차 · 임원 면접"), 상태는 색 칩(`StepStatusChip`: 예정 회색, 진행 중 빨간 점, 평가 대기, 결정 대기 파랑, 합격 초록, 보류 노랑, 불합격 빨강)으로 따로. 목록 행의 진행 표시는 `ProgressTrail`("서류 ✓ · 1차 ✓ · 2차 ●"), 지원자 상세는 `RoundStepper`(서류 → 각 차수 → 최종, 단계마다 결과와 날짜). 차수에는 색을 쓰지 않는다.

### 서류 선별

- 목록은 **접수순**(오래된 것부터)이 기본이다. AI 적합도 순으로 시작하면 사람이 AI 순위를 따라가게 된다. 적합도·경력·가명 머리를 눌러 바꿀 수 있고, 고른 정렬은 사용자마다 이 브라우저에 기억한다(`localStorage` `screening-sort:{면접관 id}`, 막혀 있으면 이번 화면에서만).
- 경력 연수는 어디서나 한 형식이다: 7.2 → "7년 2개월", 7 → "7년"(`lib/labels.ts` `formatYears`, 백엔드 `prompts.years_text`와 같다).
- 지원자 상세(시트): 위쪽 이전·다음 버튼과 ←/→ 키로 목록의 지금 순서(필터·정렬 반영)대로 옮겨 다니고 `?app=`이 따라 바뀐다. 입력란·상태 전환(라디오)·탭·메뉴에 초점이 있거나 다른 대화상자가 떠 있으면 화살표는 그쪽 몫이다.
- 선별 근거(`ScreeningRationale.vue`): screening-v0.5 지원서는 JD 요건 표(필수 먼저, 요건 · 판단 충족/미충족/확인 필요 · 근거와 위치), AI 권고 배지("AI 권고 · 보류", 사람의 상태와 다른 모양), 면접에서 확인할 점. 이전 지원서는 예전 문단(요약, + 강점, − 확인 필요)으로 보이고 첫 줄의 "(AI 권고: …)"는 배지로 옮긴다.
- 탈락: 상태에서 탈락을 고르면 사유 대화상자가 먼저 뜨고, 사유를 저장해야 상태가 바뀐다(취소하면 그대로). 사유는 상태 아래에 보이고 고칠 수 있다.
- 처리 정보(관리자만, 접힘): 선별 모델·프롬프트 버전·시각, 서류 읽기 설정 버전·읽은 도구와 버전. 다른 사람에게는 OCR로 읽은 쪽이 있을 때 "원문과 다를 수 있습니다" 한 줄만 보인다.

### 평가

- 내 점수를 내기 전에는 AI 점수·근거가 가려진다(서버가 보내지 않음, `ai.hidden`). AI 근거 카드에 "내 점수를 먼저 제출하세요"와 "그래도 보기"가 있고, 확인 대화상자를 거쳐야 열린다(감사 로그). 제출하면 바로 보인다. 패널이 아닌 사람과 결정하는 사람은 처음부터 본다. 보이는 동안에는 "AI 점수 가리기" 스위치로 다시 가릴 수 있다.

```
frontend/src/
  api/          # types.ts(모델과 1:1), endpoints, TanStack Query composable, SSE 파서
  mocks/        # 모의 API: 가상 데이터, 핸들러, 실시간 전사·꼬리질문 스트림 흉내, 모델 설정
  features/     # 화면: dashboard, postings, screening, sessions, interview(실시간, audio/ 마이크), evaluation, schedule, bank(질문 은행), admin(모델 설정, 꼬리질문 지표), intake(연동 현황), misc
  components/   # 공통 컴포넌트와 ui/ (shadcn-vue 방식)
```

## 실시간 면접 화면

면접관은 노트북으로 지원자와 이야기하면서 화면을 힐끗 본다. 그래서 다음에 필요한 것만, 한눈에 읽히게, 키보드로 쓸 수 있게 둔다. 코드는 `features/interview/`(`LiveRoom.vue`가 배치).

**면접 모드.** 진행 중인 면접 화면에 들어가면 앱 사이드바와 위쪽 검색 줄이 접힌다(`components/layout/interview-mode.ts`). 면접 화면 머리의 맨 왼쪽 버튼("메뉴 펼치기"/"메뉴 접기")으로 다시 펴고 접는다. 화면을 나가면(면접 목록, 종료) 원래대로 돌아오고, 면접 화면에 들어올 때마다 접힌 채로 시작한다. 접혀 있어도 Ctrl/⌘+K는 된다.

**배치.** 창이 아니라 면접 화면 자체의 너비로 정한다(`room-layout.ts`, 메뉴를 펴면 그만큼 좁아진다).

| 면접 화면 너비 | 배치 | 예 (면접 모드) |
|---|---|---|
| 1080px 이상 | 세 칸: 사전 질문·지원자(탭, 사전 질문 먼저) │ Q&A │ 꼬리질문·메모 | 1280·1366·1536 (100%), 1229 (1536 125%), 1093 (1366 125%) |
| 760~1079px | 두 칸: Q&A │ 꼬리질문·사전 질문·지원자 탭 + 메모 | 1024 (1280 125%, 1536 150%), 911 (1366 150%), 853 (1280 150%) |
| 760px 미만 | 한 칸으로 쌓음 | 휴대폰, 아주 좁은 창 |

탭으로 숨은 쪽에 새 꼬리질문 후보가 오면 "꼬리질문" 탭에 점이 뜬다. 지원자 요약은 시작 전 화면에서 이미 읽었으므로 면접 중에는 사전 질문 뒤 탭에 둔다.

**Q&A는 가운데 한 곳에만.** 녹음 면접은 전사를 질문별로 묶어 보여 주고(`TranscriptView`, `buildBlocks`), 전사가 듣지 못한 질문(전사가 끊긴 동안 고른 질문, 세그먼트가 오기 직전)도 번호 순서대로 자리를 잡으며, 손으로 적은 답변은 "수기 기록"으로 그 아래에 붙는다. 수기 모드(녹음 동의 없음)는 `ManualLog`. 오른쪽 칸은 다음에 물을 것(꼬리질문)과 메모만: 메모 입력란은 칸 아래에 늘 있고 지난 메모는 접어 둔다. 가운데 위에는 지금 질문(가장 최근 질문)을 크게 보이고 답변 상태(듣는 중, 아래에 기록, 답변 끝)를 붙인다.

**키보드.**

| 키 | 하는 일 |
|---|---|
| 1~9 | 그 번호의 꼬리질문 후보를 질문으로 기록("이 질문 사용"과 같음) |
| Shift+1~9 | 그 후보를 고쳐 쓰기 시작(입력란에서 Enter 기록, Esc 취소) |
| / | 직접 질문 입력란으로 |
| Esc | 입력란(직접 질문, 메모, 수기 답변)에서 나와 숫자 키로 돌아감 |
| Alt+1 / Alt+2 | 마이크: 질문 중 / 답변 듣는 중 ([audio-input.md](audio-input.md)) |
| Ctrl/⌘+K | 명령 팔레트 |

숫자 키는 입력란에 초점이 있을 때(그때는 글자), 대화상자·목록이 열려 있을 때, Alt·Ctrl·⌘와 함께일 때는 쉰다(`room-keys.ts`). 입력 중에는 후보 아래 안내가 "입력 중에는 숫자 키가 쉽니다"로 바뀐다. 다른 탭에 가려진 후보는 고르지 않고, 숫자 키가 꼬리질문 탭을 연다. 키를 눌러도 면접관이 고른 것만 기록된다는 규칙은 같다(AI가 스스로 묻지 않음). 후보 카드에는 번호와 키가 보이고 버튼에 `aria-keyshortcuts`가 있다.

**시간.** 머리에 "60분 중 42분"과 막대를 보인다(`lib/session-clock.ts`).

- 예정 길이: 차수에 면접 길이가 아직 없어 기본 60분이다. 면접을 잡을 때 서버가 한 면접을 1시간으로 센다(`api/routes/schedule.py` `BOOKED_MINUTES`)는 것과 맞춘 값이다. 차수에 길이가 생기면 `DEFAULT_PLANNED_MINUTES` 대신 그 값을 넘기면 된다(`formatClock`·`clockPhase`가 예정 길이를 받는다).
- 예정을 넘으면 노란색 "1시간 12분 (12분 초과)". 면접이 길어지는 것은 흔해서 알림은 띄우지 않는다.
- 예정의 두 배(120분) 이상 열려 있으면 거의 틀림없이 종료를 잊은 것으로 본다(패널 면접이 그렇게 길지 않고, 다음 예약 시간도 이미 지났다). 시간은 빨간색 "37시간 46분째"가 되고, 면접 화면 위에 띠가 뜬다: 몇 시간째 열려 있는지와 시작 시각, "면접 종료…"(종료 확인 창을 엶) / "1시간 뒤 다시 알림". 다시 열면 띠는 다시 뜬다. 다른 화면에서는 사이드바의 "진행 중 면접" 링크에 "… · 종료 필요"가 붙는다. 종료는 사람이 확인 창에서 누를 때만 된다.

## 모의 API 모드

```bash
cd frontend
npm ci
npm run dev          # → http://localhost:5173
```

`VITE_USE_MOCKS=true`(`.env.development`)면 브라우저의 MSW가 `/api` 요청에 답한다. 가상 데이터(공고 3 중 P1은 1차 직무·2차 임원 면접, 지원자 20, 면접관 5, 진행 중 면접 2(1차·2차), 예정 3(2차 1), 완료 9, 차수 결정 합격·보류·보류 뒤 불합격, 최종 합격 후보 1)는 새로고침하면 처음 상태로 돌아간다. 백엔드 시드(`seed_demo.py`)와 같은 배치다. 진행 중 면접 화면을 열면 지원자 답변이 글자 단위로 스트리밍되고, 답변이 끝나면 꼬리질문 후보가 스트리밍된다. 모델 설정 화면도 같은 흐름(다운로드 진행률, 연결 테스트, 외부 전송 경고, 이력·되돌리기)으로 동작한다. 연동 현황은 지어낸 수신 이력(반영, 이전 버전 건너뜀, 모르는 공고 번호·HWP·스캔본 실패, 받지 않는 항목 거절)으로 시작하고, 공고 P3에 `DS-2026-0103`을 연결한 뒤 "모르는 공고 번호 모두 다시 처리"를 누르면 지원서가 들어온다.

모의 모드에서 `/api`가 모두 502로 실패하면 브라우저가 MSW 서비스 워커를 재시작해 등록이 풀린 것이다. 새로고침하면 된다.

## 백엔드 연결 모드

같은 `/api` 경로를 Vite 프록시로 FastAPI(`localhost:8000`)에 보낸다. 대상은 `frontend/.env.api`의 `VITE_API_PROXY_TARGET`. 데이터는 DB에서 오고 새로고침해도 남는다. [setup.md](setup.md)대로 마이그레이션·시드를 한 뒤:

```bash
uv run uvicorn interview_assistant.main:app --reload   # 저장소 루트에서
cd frontend && npm run dev:api                         # → http://localhost:5173
```

서류 선별 화면의 "서류 업로드"로 PDF·DOCX·PPTX·HTML·HWP·HWPX·구형 .doc/.ppt·JPG/PNG를 올리면 읽기 → 비식별화 → 프로필·선별 → 표에 새 가명(CAND-0021 …)으로 들어온다. 스캔본과 사진은 관리자가 정한 읽기 방식대로 OCR로 읽는다([document-reading.md](document-reading.md)). 이름·연락처는 비식별화에만 쓰인다. 테스트용 가상 이력서는 `tests/fixtures/resumes/`에 있다.

## 의존성과 라이선스

- 버전은 `package.json`에 정확히 고정하고 `package-lock.json`을 커밋한다(공개 후 2주 이상 지난 버전). 의존성을 바꿀 때는 `npm install --before=<2주 전 날짜>`로 설치해 전이 의존성까지 같은 기준을 지킨다.
- 번들에 들어가는 라이브러리는 MIT·ISC·Apache-2.0·BSD 계열이고 폰트는 OFL-1.1이다.
- 빌드·테스트에만 쓰고 번들에 들어가지 않는 예외: lightningcss(MPL-2.0, Tailwind v4와 Vite의 CSS 처리), jsdom이 쓰는 mdn-data(CC0-1.0)와 @csstools/*(MIT-0), glob·minimatch·lru-cache 등(BlueOak-1.0.0).
