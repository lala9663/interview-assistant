# AI 면접 어시스턴트 구현 순서

2026-10-21 · 김태윤 · 원본(수정은 여기서): https://claude.ai/artifact/4FK2UfGeYhV1CVscCVaTP4

Phase 1 PoC(6주 추정)를 13단계로 나눈다. 오디오 없는 텍스트 흐름을 4주 안에 끝내고, 오디오와 실시간은 5~6주에 얹는다. 저장소: https://github.com/lala9663/interview-assistant · 업무정의서: https://claude.ai/artifact/KHpkqy2oKKChicmheA2byK

## 1. 순서를 정하는 원칙

- 텍스트부터 끝까지: 오디오 없이 서류 → 면접(텍스트 입력) → 평점 흐름을 먼저 완성한다(1~9단계). 오디오와 실시간은 그 위에 얹는다(10~11단계).
- fake 먼저, 실제 모델은 교체로: 모든 기능은 fake provider로 테스트를 통과시킨 뒤 providers.yaml만 바꿔 실제 모델을 붙인다.
- 비식별화가 실제 LLM 호출보다 앞: 지원자 데이터가 모델로 가기 전에 2단계가 끝나 있어야 한다.
- 단계마다 Claude Code 세션 1개(새 카드)에서 진행한다. 개인 프로젝트라 PR 없이 main에 직접 커밋하고, 테스트 통과 후 푸시한다. 완료 기준을 통과해야 다음 단계를 시작한다.
- 사용자 결정이 필요한 것(0단계)은 병목이 되지 않게 1단계와 같은 주에 처리한다. 1단계는 결정 없이도 시작할 수 있다.

## 2. 시작 전에 정할 것

아래 다섯 가지는 특정 단계를 막는다. 결정되면 업무정의서 11장 미결 사항에도 반영한다.

| 항목 | 선택지 | 권장 | 막히는 단계 |
| --- | --- | --- | --- |
| DB 엔진 | PostgreSQL / MySQL | 사내 표준을 따른다. 없으면 PostgreSQL. SQLAlchemy라 1단계는 SQLite로 먼저 진행 가능 | 1 (마이그레이션 확정 시점) |
| GCP 프로젝트와 리전 | 신규 프로젝트, asia-northeast3 또는 global 엔드포인트 | PoC는 global, 리전 제약은 Phase 2에서 | 3, 10 |
| 대상 직군 1개 | 채용팀과 협의 | 샘플 JD와 서류를 구할 수 있는 직군 | 4, 5 |
| 샘플 데이터 | JD 1건, 서류 10건, 녹음 1건 | 실제 데이터가 어려우면 익명화 샘플 또는 가상 데이터 | 4, 5, 10 |
| 비대면 통화 방식 | 앱 내 WebRTC / 기존 화상회의 툴 | 앱 내 WebRTC (LiveKit) | 11 |

## 3. 단계 순서

단계 번호가 기본 순서다. 선행 단계가 다르면 병렬로 진행할 수 있다 (예: 3과 4, 8과 9). 주차는 개발자 2~3명 기준 추정치다.

| 단계 | 작업 | 포함 내용 | 선행 | 완료 기준 | 주차 |
| --- | --- | --- | --- | --- | --- |
| 0 | 결정 확정 | 2장의 다섯 항목 답변, GCP 프로젝트 생성과 API 활성화, 서비스 계정 발급 | 없음 | 다섯 항목 확정, Vertex AI 호출 1회 성공 | 1 |
| 1 | 도메인 모델·DB | 업무정의서 6장 엔티티 13개를 SQLAlchemy 모델로, Alembic 초기 마이그레이션, SQLite로 로컬 테스트 | 없음 (엔진 확정 전에도 가능) | 마이그레이션 적용·롤백, 모델 테스트 통과 | 1 |
| 2 | 비식별화 모듈 | 이름·연락처·학교·회사 토큰 치환, 역매핑 테이블 저장, 누출 검수 스크립트 | 1 | 샘플 20건 수동 검수 누출 0건 | 1~2 |
| 3 | 실제 LLM Provider | anthropic_vertex 구현(구조화 출력, 스트리밍, 토큰 집계), 감사 로그 저장, 프롬프트 캐싱 | 0, 1 | fake와 동일 테스트 통과, 실제 호출에서 구조화 출력 검증 | 2 |
| 4 | 역량 사전 (FR-02) | JD → 역량 목록과 1~5점 BARS 초안 생성, 검토 후 확정본을 DB에 버전으로 저장 | 3, 샘플 JD | 대상 직군 역량 사전 v1 확정 | 2 |
| 5 | 서류 파싱·선별 (FR-01, 03) | PDF/DOCX 파싱, 프로필 구조화 추출, JD·역량 기준 적합도와 근거, 순위 저장 | 2, 3, 4 | 샘플 서류 10건 선별 결과와 근거 저장 | 3 |
| 6 | 면접 세션·기록 (FR-04, 06 저장, 08) | 세션 생성, 면접관 등록, Q&A 저장, 지원자 메모. 텍스트 입력 기준(오디오 없음) | 1 | API로 세션 1건 전 과정 저장 | 3 |
| 7 | 질문·꼬리질문 (FR-06) | 사전 질문 세트, 직전 답변 기반 꼬리질문 2~3개 스트리밍, 선택 기록 | 4, 6 | 텍스트 답변 입력 후 2초 내 첫 토큰 | 3~4 |
| 8 | 평점 (FR-07) | 역량별 1~5점, 근거 인용 필수, 3회 샘플 집계와 신뢰도, 면접관 점수 별도 저장 | 2, 4, 6 | 평점 JSON 스키마 검증, 근거 없는 점수 거부 | 4 |
| 9 | 면접관 UI (최소) | 세션 화면: 지원자 카드, 트랜스크립트, 꼬리질문 후보, 평점 입력 | 6, 7 | 면접관 1명이 텍스트 모의 면접 완주 | 4 |
| 10 | STT 배치 (FR-05 사후) | google_stt_v2 배치 전사와 화자분리, 녹음 업로드 → Q&A 분할 | 0, 6 | 샘플 녹음 1건 전사·화자분리 저장 | 5 |
| 11 | 비대면 실시간 (FR-05) | WebRTC 통화(LiveKit), 스트리밍 STT, 실시간 꼬리질문 | 7, 9, 10 | 모의 비대면 면접 1건 완주, 부분 전사 0.5초 이하 | 5~6 |
| 12 | 평가셋·게이트 1 | 면접관 점수 대비 일치도, 비식별 누출률, 1건당 비용, LLM/STT 교체 1회 검증 | 8, 10 | 게이트 1 기준 4개 충족 리포트 | 6 |
| 후순위 | 스케줄 매칭 (FR-09) | 수기 가용 시간 입력과 교집합 | 1 | Phase 2 | - |
